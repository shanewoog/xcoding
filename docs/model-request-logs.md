# 模型请求日志

进入 **设置 → 日志查询**，开启页首的 **记录模型请求详情**，点击顶部 **保存设置**。开关默认关闭，对保存后发起的新模型请求生效。

- 查询默认返回最新 10 条，可按开始/结束时间、模型名称、请求地址和状态组合筛选，支持每页 10 条翻页。
- 点击 **查看详情** 查看发送的请求 Headers、POST JSON、原始响应正文（流式请求为 SSE）、HTTP 状态、耗时和错误。时间筛选使用本机时区。
- Headers 在初始请求构建后、发送前记录，包含 User-Agent、Content-Type、Host、Content-Length 和协议专用头；Host、Content-Length 等 HTTP 客户端自动生成的字段按该请求补全。不包含代理 CONNECT 或重定向衍生请求。旧日志未记录的 Headers 无法补回。
- 覆盖 Chat Completions、Responses 和 Anthropic Messages，包括重试及摘要等辅助模型调用。不记录模型列表查询。
- 请求结束后保存响应正文；失败和正常取消也保存已接收到的部分。强制结束进程可能留下“请求中”记录且丢失尚未写入的响应。
- 日志存于用户配置目录的独立 SQLite 文件 `model-request-logs.db`，查询或写入时按 **默认值 → 模型调用日志保存天数** 清理过期记录。关闭开关不删除历史日志，也不影响原有调用摘要和报表。
- Authorization、API Key、Cookie 等敏感头保留名称、值显示为 [REDACTED]；URL 用户信息、查询参数、片段被移除；请求 JSON 的鉴权字段与当前使用的 API Key 脱敏。正文仍可能包含其他业务机密、代码或用户输入中的凭据，不保证自动识别所有敏感内容。
- 请求、响应正文各最多保留 8 MiB，超出时显示截断提示，不影响实际请求。详细记录有本地磁盘/序列化开销，建议仅在排查问题期间启用。

日志仅保存在本机，不会自动上传。旧版本未记录的请求正文无法补回。

模型侧由程序生成的身份描述、工具输出截断标记和命令策略提示统一使用 Codex。用户输入、历史消息、仓库规则、技能内容、代码和真实路径中的 XCoding 保留原文，不对整个请求做全文替换；因此请求日志中仍可能出现这些原始内容里的 XCoding。应用名称和配置目录保持不变。
